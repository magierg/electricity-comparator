# Verify the electricity plan comparator

This is a static React + Vite app. It has no backend, authentication, or database.
The dataset is generated by `scripts/build-plans.mjs`; the app reads
`src/data/wellington-plans.ts`.

## Launch

Start the app on a fixed port:

```bash
npm run dev -- --host 127.0.0.1 --port 5173
```

The app is ready when `http://127.0.0.1:5173/` returns a 2xx or 3xx response and
the page contains `Wellington electricity plan comparison`.

For a production build:

```bash
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
```

## Doctor

Before driving an instance, check:

```bash
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5173/
```

If the port is already owned by a stale process, start on another port and pass
the URL to the harness. Do not kill processes by name.

## Drive

### Deterministic Playwright

```bash
npx playwright test
```

The existing suite covers the main ranking flow, annual estimate, current-plan
comparison, and invalid CSV handling.

### Agentic exploration

```bash
npx e2e explore \
  "Explore the app like a first-time user. Exercise the annual estimate, custom hourly usage, CSV upload, plan ranking, filters, current-plan comparison, and peak windows. Report only issues with concrete evidence." \
  --max-steps 8 \
  --timeout 600000
```

The e2e config starts Vite itself. Do not start a second dev server on port 5173
when using `e2e explore`.

## Evidence

Capture:

- the action that was taken;
- the resulting visible state (text, role, selected value, error message);
- a screenshot for visual or layout findings;
- console errors if the UI appears broken.

Store temporary evidence under `.exploratory/evidence/`; it is ignored by Git.
`e2e` writes its own report to `.e2e/report.json` and screenshots under `.e2e/`.
Proof must exercise the user path, not a test-only setter.

## Cleanup

Stop only the process you started. Remove `.exploratory/` scratch files before
finishing. Never delete `.e2e/` evidence before the report is read; the workflow
uploads it as an artifact.

## Feature map

### Usage input

- Tabs: **Sample data**, **Annual estimate**, **Custom 24-hour**, **Upload meter CSV**.
- Annual estimate accepts a kWh/year value and suggests low or standard user.
- CSV upload accepts a half-hour meter CSV and reports invalid format errors.

### Plan ranking

- Plans are ranked by annual cost.
- Provider and plan-type filters narrow the list.
- Each plan expands to a cost breakdown.
- Best value and 17-plan count are visible.

### Current plan comparison

- Selecting a current plan shows potential annual savings and the switching
  comparison.

### Peak windows

- Peak and shoulder hours are editable.
- Changing the windows changes time-of-use plan costs.

### First-year estimate

- One-off credits, percentage discounts, and free-power hours affect the
  first-year estimate without changing the ongoing annual ranking.

## Gotchas

- All rates are GST-inclusive; do not add GST again.
- The dataset is Wellington-only, October 2026.
- Peak windows are an app assumption, not retailer data.
- The source dataset has two documented annual-validation exceptions in
  `scripts/build-plans.mjs`.
- The app uses `Intl.NumberFormat` with NZD; locale changes can change spacing.
