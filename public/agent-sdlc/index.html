Design goals

Small changes. Hard evidence. Human judgment.

The pipeline is shaped around one constraint: a wrong cost calculation is worse than a slow merge. Every gate exists to make the risky path visible before it ships.

Bounded by default

Agents get a narrow permission list, a step cap, and no path to workflows, dependencies, generated data, or scripts.

Evidence before merge

CI, a Jev risk assessment, and an exploratory agent produce labels and statuses that a reviewer can inspect.

Human at the gate

Phase 1 requires an approval. Auto-merge is limited to docs-only and tests-only changes; everything else is a deliberate merge.

Reversible by design

Small squash-merged pull requests, deleted branches, and a risk correction label make it cheap to undo a bad call.

    Playbook

    Work the issue. Then work the checks.

    A practical path from an agent:ready issue to a green, reviewed pull request. Green checks are necessary; they are not a substitute for the human gate.

    01

    Start an issue

    1. Write the problem, acceptance criteria, and constraints in the issue.
    2. Add agent:ready.
    3. Comment /oc plan. Review the plan and test strategy.
    4. Comment /oc implement. The agent opens a PR with Closes #N.

    Commands are limited to owners, members, and collaborators. The implementer refuses if an agent PR is already open for the issue.

    02

    Work the PR

    1. Read the risk comment and labels before reading the diff.
    2. Run /oc review for a read-only second pass.
    3. Fix red checks locally, or use /oc fix checks.
    4. Review exploratory evidence. Re-run with exploratory:run after new commits.
    5. Request human review when the evidence is complete.
    03

    Get to green

    1. Run the local preflight that matches the change.
    2. Use gh pr checks <n> to find the first red job.
    3. Read the failing log with gh run view <run-id> --log-failed.
    4. Fix the root cause and push. Do not weaken a test to clear a check.
    5. Wait for ci-success, get approval, then merge.

    Auto-merge is limited to low-risk docs/tests. UI and sensitive changes are squash-merged manually after approval.

    Check recovery map

    What each check proves and the first local command to run when it is red.

    Required merge checks: ci-success · risk · dependency-review
    Check Run locally If it is red
    lint npm run lint:ci
    npm run typecheck    		 Fix the first ESLint or TypeScript error. The same job runs actionlint over workflow YAML.
    unit npm test
    npm run test:scripts
    npm run test:coverage     		Add or fix a focused test. Never weaken an assertion to clear the check.
    build npm run build
    npm run build-storybook    		 Fix the TypeScript, Vite, or Storybook error. Check the generated output.
    data npm run data:plans:check Do not hand-edit src/data/**. Rerun the generator only when the source data changed.
    e2e npm run test:e2e Open the playwright-report artifact. Fix the flow or use /oc fix checks.
    security npm audit --omit=dev --audit-level=high Update the dependency or document the accepted risk.
    dependency-review GitHub check on dependency diffs Split or justify the dependency change. High-severity additions fail.
    risk Read the PR Risk comment and labels risk:unknown means the classifier failed. risk:high needs human review. risk:accepted only permits a manual merge.
    exploratory Review the PR comment and exploratory-report artifact Fix the finding, re-run with exploratory:run, or accept an unrelated pre-existing finding with a linked issue.
    ci-success Wait for the aggregate One of changes, lint, unit, build, data, e2e, or security failed. Open that job.
    preview-e2e Vercel preview + Playwright check Check the Vercel deployment first, then inspect the preview Playwright report.
    CodeQL GitHub code scanning Fix the alert or dismiss it with a documented reason.

    The gate job is the auto-merge eligibility evaluator. It is expected to stay blocked for UI and sensitive changes; read its reasons rather than treating the block as a test failure.

    Before you merge

    Green checks are evidence. The merge decision still belongs to a human.

    • The issue is linked with Closes #N.
    • Tests cover the behavior; UI changes have Playwright or exploratory evidence.
    • Local preflight passes; generated data is unchanged unless the source changed.
    • The risk label is understood; high or unknown has human review.
    • The exploratory report was reviewed; acceptance links to an issue.
    • No do-not-merge; approval is recorded.

    Unrelated exploratory finding?

    Confirm it reproduces on main and is not caused by this PR. Open a focused issue with the evidence, add exploratory:accepted with a comment linking that issue, and merge manually. Keep the gate intact for the next change.

    Command cheat sheet

    Commands are limited to repository owners, members, and collaborators.

    PR commands need environment approval
    Command Where Agent Effect
    /oc plan Issue Planner Posts a read-only implementation and test plan.
    /oc implement Issue Implementer Opens an agent branch and a pull request.
    /oc review Pull request Reviewer Posts read-only review findings.
    /oc fix checks Pull request Babysitter Diagnoses and pushes a fix for failing checks.

    PR commands refuse forks, stale commands, and pull requests that changed agent configuration. The implementer refuses a second open agent PR for the same issue.

    Edit* is the important nuance: an implementer or babysitter can edit calculation logic, but the risk workflow classifies it as sensitive. It can never auto-merge and needs human review.

    Trusted base

    Risk classification runs on pull_request_target from the base branch and never checks out or executes PR code.

    Environment gate

    PR command jobs run in the opencode-pr environment. A required reviewer releases the API key and PR code.

    Config drift guard

    If a PR changes opencode*.json, AGENTS.md, or .opencode/**, PR commands refuse and ask for a manual run.

    Stale command guard

    A command posted before the latest push is rejected. Re-post it after the new head is available.

    Fork boundary

    Fork PRs skip agent and exploratory jobs because repository secrets are not available to them. They need manual review.

    Cost caps

    Step limits, job timeouts, concurrency groups, and an eight-step exploration budget keep agent runs bounded.

    Field notes

    When a gate says no

    The short version of the runbook. Use the authenticated gh CLI for CI debugging; the browser is not the source of truth.

    Why didn’t auto-merge enable?

    Auto-merge needs all of these at the same time:

    • The PR is not a draft and has no do-not-merge label.
    • risk:low and automerge:eligible are both present.
    • The change is docs-only or tests-only on a non-sensitive path.
    • The diff was not truncated by the classifier limit.
    • For UI changes, exploratory:passed or exploratory:accepted is present.
    • Phase 1 has an approving review, unless AUTOMERGE_REQUIRE_APPROVAL=false.

    UI changes are not auto-merge eligible in the current policy, even after a passing exploratory run. risk:accepted overrides the risk status only; it does not enable auto-merge.

    Why is risk unknown?

    Jev could not produce a usable result. Missing or invalid OPENCODE_API_KEY, model unavailability, and timeouts produce risk:unknown. Check the PR Risk workflow, the uploaded risk-result.json, and the PR comment. A diff over the classifier limit can still get a risk label, but it is never auto-merge eligible. Auto-merge stays blocked until the risk is resolved.

    Why didn’t exploratory testing run?

    It runs on PR open, reopen, or ready-for-review, and when the exploratory:run label is added. It does not run on every push. Tests-only changes and fork PRs are skipped. To re-run after new commits, add exploratory:run; the workflow removes it after the run.

    Why did a PR command refuse?

    Common reasons:

    • The PR comes from a fork.
    • The comment predates the latest push.
    • The PR changed agent configuration.
    • The opencode-pr environment approval was not granted.
    • The command was posted by someone outside the owner/member/collaborator set.
    How do I override a gate?

    risk:accepted lets a maintainer merge manually after reviewing the risk; it never enables auto-merge. exploratory:accepted should be added only after reading the exploratory report artifact. do-not-merge stops auto-merge immediately. Phase 2 can be enabled by setting AUTOMERGE_REQUIRE_APPROVAL=false after calibration.

    Where should I debug a red check?

    Use the authenticated GitHub CLI:

    gh pr checks <pr-number>
gh run list --limit 20
gh run view <run-id> --log-failed
gh run download <run-id> -n <artifact-name> -D /tmp/ci-artifacts

    The runbook has the full triage path and the weekly calibration report.
